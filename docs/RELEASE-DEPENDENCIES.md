## Autres correctifs directs et limites

DOMPurify est utilisé pour le HTML des articles côté backend et navigateur : correction des avis XSS prioritaires, test de conservation du contenu et suppression de script/onerror/javascript ajouté. Mongoose est mis à jour dans la majeure 9 pour corriger la pollution de prototype; le comportement du modèle et les contrôles TypeScript sont conservés. Aucun serveur MongoDB réel n’est utilisé par les tests de révocation (frontière de stockage simulée).

Express 4.22.2 fixe encore qs à 6.15.3. Deux alertes moderate (qs et propagation à Express) restent: parsing comma et isBuffer. L’application utilise express.json avec limite 1 Mo et ne configure pas comma:true ni un isBuffer fourni par le client. Risque résiduel de parsing des query strings; ne pas assimiler cette analyse à une preuve d’inexploitabilité. Le correctif qs 6.16.0 est disponible, mais imposer un override au-delà de la version exacte d’Express mérite une validation séparée. Aucun critical/high backend n’est conservé.

L’erreur interne edgesOut de npm 10 lors de la mise à jour de Vitest a nécessité une exécution ponctuelle de npm 11, sans installation globale. La compatibilité du lockfile avec npm ci 10 doit être vérifiée avant release.
## Résultat final des dépendances

`npm ci` a réussi avec npm 10.9.4 dans les deux sous-projets. Aucun contournement des peer dependencies n'est nécessaire à l'installation du lockfile final.

| Projet | Critical | High | Moderate | Low |
|---|---:|---:|---:|---:|
| Racine | 0 | 0 | 0 | 0 |
| Backend | 0 | 0 | 2 | 0 |
| Frontend | 0 | 0 | 0 | 0 |

Les deux entrées backend correspondent à `qs` et à sa propagation vers Express. Le mode `comma:true` n'est pas activé dans l'application. Source primaire : [avis du mainteneur qs](https://github.com/ljharb/qs/security/advisories/GHSA-x5fp-wj9c-mxmx). Le correctif annoncé est 6.16.0 ; aucun override n'est imposé à la dépendance exacte d'Express dans cette release.

Les dépendances effectives de production sont Express/path-to-regexp/undici côté serveur et Axios/React Router côté navigateur. Les autres lignes critical/high concernent les outils de développement ou les chaînes de build/test ; `form-data` reste une dépendance installée de l'adaptateur Node d'Axios, qui n'est pas utilisé par le frontend navigateur. DOMPurify et Mongoose (avis moderate) ont également été corrigés.
